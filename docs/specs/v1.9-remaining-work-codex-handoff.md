## 2. The invariants you MUST preserve (these are why prior reviews passed)

1. **Two gates, in this order, before any hard command applies** (`apply_narrative_director`):
   - `_backbone_reason(world, state, effects)` (Q1/Q4): reject if applying the effects would make a backbone `prohibited_predicate` true, or REVERSE a currently-held `irreversible_fact`. Reuses real `apply_effects` + real `evaluate_condition` over a dry copy. **Fail-closed on any eval error.**
   - `mandatory_reachable_after(world, state, effects, now)` (Q3): forward-replay with vs without the effects to the last pending mandatory anchor, reusing the **real `EventDispatcher` + real `apply_effects`**; require identical mandatory firings. **Fail-closed** on any horizon event that isn't fully modellable (`_event_fully_modellable`).
2. **Single source of truth, no drift:** a command → CANONICAL effects (`_command_effects`) that drive BOTH the dry-run gates AND the real application via `apply_effects`. Never hand-roll an effect twice. (This is the lesson behind every M1a P0.)
3. **Persistence lands in the DURABLE store, not the ephemeral one.** `world.world_flags` is NEVER serialized — flag writes must be mirrored into `sc.state["world_flags"]`. Relations live in `sc.state["relations"]`; vars ARE `sc.state` (via `scripted_scenario_state`). Verify where your new effect's state lives and mirror if needed. (M1b P0.)
4. **Deterministic replay (M2a):** a decided turn is frozen in `sc.director_cache` (key = month + backbone-hash + locale). A cache HIT replays narration ONLY — no LLM call, no re-apply (effects already in `sc.state`). The cache lookup is BEFORE the generator guard. Don't break this.
5. **Backbone predicates must be deterministic** — `_validate_backbone` (in `scenario_loader.py`) allow-lists deterministic builtins only (rejects `random_chance`, mod/unknown). A hard gate decided by one dry eval can't be a coin flip.
6. **Snapshot-only boundary:** `_build_director_snapshot` returns COPIES (deep-copy nested). The director never gets the live world.
7. **Prompt anti-injection:** every authored/snapshot value interpolated into the prompt goes through `_clip` (neutralizes `<<<`/`>>>` + length-caps) inside the fenced reference block.
8. **Degrade:** no LLM key / generator / failure → `[]`; mandatory anchors still fire (scripted skeleton stays playable).

## 3. Remaining work (priority order)

Each item below is its OWN milestone — a tight slice with its own negative tests, full-suite green, and a spec-log entry. **Do NOT bundle them.**

### 3a. `director_set_var` is done — the next 3 commands are the HARD ones
They were deferred precisely because each needs real gate-modelling design. For each: decide whether the effect is **soundly modellable in the reachability gate**, or whether the command must **fail-closed** (rejected) whenever a mandatory horizon depends on the affected state. When in doubt, fail-closed (honest + safe) and say so in the spec.

- **`introduce_minor_npc`** (hardest). Problems: (1) `spawn_npc` (`effect_applier.py:241`) is a standalone function, NOT a canonical `apply_effects` effect type — you'd need a canonical effect or special-case it (breaking the single-source pattern; think hard). (2) The gate's `_build_dry_state` has NO npcs, so any mandatory predicate reading npc state (`npc_alive`/`npc_realm`/`npc_relation`) already fails closed — fine, but means an introduced NPC can't be modelled in-horizon. (3) A director-proposed NPC needs a full valid avatar spec (id/name/realm/alignment/…); validate strictly. Persistence: npcs live in `sc.state["npcs"]` (a dict) → durable like relations, but confirm. Suggested first cut: only allow introducing a **flavor NPC with no mechanical hooks** (no relations/realm that any anchor reads), fail-closed otherwise.
- **`emit_director_event`** — emitting a scenario event touches scheduling/priority (Q6). Do NOT reuse the `world_event_trigger` effect (it writes `triggered_event_ids` and can fake a mandatory as already-fired — `effect_applier.py:165`; this was an explicit Q2 rejection). Design a director-owned event channel + decide how the emitted event interacts with the dispatcher ordering. Heavy; may need the central-scheduler work below first.
- **`local_crisis`** — composite (multiple effects in one beat). Compose from already-gated primitives; the gate must evaluate the COMBINED effect set. Probably the last one.

### 3b. `protected entity/faction IDs` (Q1 backbone extension)
Add `protected_ids` to the backbone (machine-checkable): the director may not kill/remove/reassign a protected entity or faction. Pairs naturally with the npc/faction commands above — implement alongside them, not before (premature otherwise). Validate + gate in `_backbone_reason`.

### 3c. Pre-existing gap (already flagged as a task) — normal-event flag persistence
`apply_effects` `set_flag`/`clear_flag` write the EPHEMERAL `world.world_flags`, which is never serialized. So **normal scenario event** `set_flag` effects don't survive save/reload. The director path was worked around in M1b (mirror into `sc.state["world_flags"]`), but event-driven flags remain affected. Root-cause fix: either sync `world.world_flags` → `sc.state["world_flags"]` in `_sync_dispatch_state` (`scripted_scenario.py`), or serialize `world.world_flags` in `save_game.py`/`load_game.py`. Add a save→reload regression test. Check whether non-scenario systems also rely on `world.world_flags` before choosing.

### 3d. Further-deferred (need a central-scheduler rewrite — scope carefully, likely v1.9.x+)
- **Finer priority arbitration** (Q6): the full `mandatory > player_choice > director_main > mechanical > director_side > ambient` ordering, including splitting director beats into main/side relative to mechanical dispatch. Today only mandatory-first + director-phase ordering is structural.
- **Ambient suppression**: suppress random-minor events in months where a mandatory/director beat fired (cross-phase signal via `ctx`; `phase_random_minor_events` runs after the scripted phase).
- **Structured plot ledger** (M2 deferred part): threads / promises / secrets-who-knows with stable IDs + invalidation, and LLM far-past arc-summarization. M2b shipped recent-verbatim memory + held-irreversible-facts only.

### 3e. Open scope question for 御主 (resolve before doing 3a)
Are the 3 hard commands inside v1.9, or a v1.9.x follow-up? v1.9 core is already feature-complete and the acceptance criteria are met, so shipping v1.9 now and doing 3a–3b as v1.9.x is defensible. Confirm with 御主.

## 4. Process to follow (mirrors what worked all session)

Per milestone, in order:
1. **Tight slice** — one command/capability. Reuse real machinery; never reimplement (drift = false-green). Fail-closed on anything not exactly modelled.
2. **Negative tests first-class** — for each new command: a reachability-starve rejection, a backbone-prohibited rejection, an allowed+persists case, and validation. Mirror the existing `tests/test_scenario_director_gate.py` patterns (`_run_backbone`, `_sentinel_timeline`).
3. **Full suite green**: `.venv/bin/python -m pytest -q` → must stay at/above 1993 pass / 2 skip with zero regression. The **drift benchmark `tests/test_scenario_director_drift_benchmark.py` is the merge gate** — if a change weakens a gate, it goes red; keep it green and extend it to cover any new adversarial command path.
4. **Spec log** — append a milestone section to `docs/specs/v1.9-narrative-director.md` (implementation + decisions + any residual).
5. **Git** — own branch per milestone, ff-merge to `main`, push. Commit messages end with the Co-Authored-By trailer used in this repo's recent history.

### Gotchas that bit prior reviews
- Don't place new gating AFTER a guard that can early-return (the cache lookup P1).
- `MagicMock` attributes are truthy — set `is_dead=False` etc. explicitly in tests.
- `world.world_flags` ≠ `sc.state["world_flags"]` (ephemeral vs durable).
- Backbone constructed directly in tests bypasses the loader's determinism validation — keep test backbones deterministic anyway.
