## 边界（锁死,先于一切 —— 注意:这是对 v1.8 的【反转】)

> **v1.9 = LLM 自主生成符合走向的剧情,超越预设锚点。半 AI → 真 narrative AI。**

| | v1.8 (L3) | v1.9 (L4) |
|---|---|---|
| LLM 角色 | 锚点间**填充**(flavor) | 锚点间/外**自主演化走向**(director) |
| 走向 | scripted 锚点定死,beat 不可改 | **锚点 = 必达里程碑;director 在其间/外自主生成方向性事件** |
| beat 机制权限 | 仅 relation_delta(且写集合非干涉) | **受 backbone 约束的、更宽但有界的 effect 词汇**(可改走向) |
| 核心不变量 | beat 永不改变哪些事件触发 | **director 不得违反 backbone 禁忌、不得使任一 mandatory 锚点不可达** |

**v1.8 的核心不变量(beat 非干涉)在 v1.9 被【有意解除】** —— director 就是要碰走向。所以安全契约从「**非干涉**」变为「**backbone 约束 + 有界权限 + mandatory 锚点仍可达**」。

**硬不变量(架构级,不可越界)**:
1. **backbone 至上(不可变宪法)**:每个 scenario 声明一份 immutable backbone —— thesis/themes/**prohibited outcomes**/关键派系角色/**mandatory 锚点**(spike §2.1,版本化 + hash)。director 生成的任何事件**不得违反 prohibited outcomes**,**不得使任一 mandatory 锚点变得不可达**。这是 L4 取代 L3「非干涉」的新守门线。
2. **Simulator 是唯一 tick 主人 + 唯一 mutation 协调者**(spike §3):director 是**异步 planner**,只能**提议**,不能推进时间、不能直接写 world。提议经 schema/ID/condition/backbone/可达性校验后,走与所有世界改动**同一条确定性 mutation lane** 应用。director **不接收可变 world**,只收不可变快照,返回受校验数据(继承 v1.8 snapshot-only)。
3. **有界权限(authority boundary —— L4 最关键决策,spike §5.1)**:director 提议的事件能 mutate 什么?比 L3(仅 relation_delta)宽,但**仍是白名单**:**禁止**违反 backbone 的不可逆操作(复活死者、推翻已定派系归属、违反 prohibited outcome);**player-exclusive / 纯机制结算**(如玩家关键抉择、战斗判定)**保留**,director 不得代行。待定具体词汇(Q2)。
4. **优先级仲裁(spike §3)**:`hard_anchor(mandatory) > player_pending_choice > accepted_director_main > mechanical_major > director_side > ambient_random`。冲突由优先级解决,不静默覆盖已应用机制。mandatory 锚点永远赢。
5. **长程连贯(plot ledger,spike §2)**:完整分层记忆 —— immutable backbone + 权威世界快照 + **plot ledger**(unresolved threads / promises / secrets / 已完成锚点 / 已废分支 / 因果事实,每条带稳定 ID + source event + 时间 + 失效状态)+ rolling digest(近期逐字 + 远期按 arc 摘要,**不可逆事实单独保全**防摘要复活死者)+ director plan state。这是 L4 区别于 L3「有界 gap 记忆」的核心新建。
6. **降级即纯锚点骨架**:无 LLM key / 失败 / 超时 → director 不提议,**mandatory 锚点照常按时触发**,游戏退化为 v1.6 scripted 骨架,完整可玩(继承 v1.8 降级)。

> v2 才把「自动从小说长出 scenario」接上;v1.9 专注「给定 backbone,LLM 自主演故事」。

### 待锁的最关键决策（M1 之前必先定)
- **Q2 director 权限词汇**(对应 v1.8 的「文本存哪」/L3 的「beat 能 mutate 什么」):L4 必然比 L3 宽(否则没有「自主演化」),但宽到哪?候选见 Q2。
- **可达性守门怎么做**:v1.8 用「beat 不改任何未来事件 condition」的强非干涉。L4 director **要**改走向 → 不能用 L3 那套。改用 **mandatory 锚点的前置可满足性 + 定时重放**:director 应用后,**所有 mandatory 锚点仍存在一条可达路径**(否则拒绝该提议)。这是 L4 守门的根本难点。

## Context / 阶梯定位 + 继承 v1.8

- roadmap **L4**(`roadmap-to-narrative-goal.md` line 42-43):LLM 理解剧本脉络 + 世界状态,自主生成符合走向的剧情(超越预设锚点)。**真 narrative AI 攻坚 —— ③ 达成,总目标灵魂落地。** 设计挑战:剧情连贯/长程记忆、剧本约束 vs 涌现、director 与模拟引擎协调、成本/延迟。
- **继承 v1.8 L3 基建(不从零造)**:
  - **snapshot-only generator 接口** + 严格超时 + 降级(`make_transition_generator` 模式)→ director 同构。
  - **专属确定性 applier + 命令白名单 + write-set 提取**(`narrative_transition`)→ L4 扩展白名单 + 校验,复用 applier 思路(**不走 `apply_effects`**,理由同 L3:rollback 不安全 + mod effect 不可控)。
  - **冻结缓存 + 确定性 replay**(`transition_cache`,gap+locale 键)→ director 提议的固化/replay 同构(键需扩,见 Q5)。
  - **审计 ledger**(`transition_ledger`,state 兄弟,持久)→ 升级为 plot ledger(带因果/失效)。
  - **anchor 概念 + load 时 timed 可达校验**(`_validate_anchor_reachability`)→ mandatory 锚点复用,可达校验升级为「director 应用后仍可达」运行时校验。
  - **render-only narration 通道 + chronicle exclude_story**(v1.7/v1.8)→ director 叙事文本同走 narration,不污染机制/记忆。
  - **proposal boundary 蓝图**(spike §1):`snapshot → director proposal → schema/ID/condition/backbone 校验 → 确定性 command 应用 → Event → ctx.events`。
- **真正新建**(L3 都没有的):① immutable **backbone**(thesis/prohibited/mandatory)+ 版本化;② **plot ledger**(长程因果记忆 + 失效);③ **优先级仲裁 + 调度**(mandatory 锚点 vs director beat vs 机制 vs ambient);④ **「应用后 mandatory 锚点仍可达」运行时校验**(取代 L3 非干涉);⑤ **长程漂移自动化 benchmark**(spike §5.2,最大未知)。

## Goal
给定一份 immutable backbone(thesis + prohibited outcomes + mandatory 锚点),让 LLM director 据世界状态 + plot ledger **自主生成符合走向、不违禁忌、不饿死 mandatory 锚点的剧情事件**(超越预设),经确定性校验后应用;可复现、可降级、长程可验。**这是总目标③「剧情自动发展」的终点。**

## 设计 Q（待御主拍 —— 先列清,不实现）

### Q1 — backbone schema
backbone 怎么声明?候选:scenario.json 加 `backbone` 段(thesis 文本 + `prohibited_outcomes: [...]` + `mandatory_anchors: [event_id...]` + 关键派系/角色白名单 + version/hash)。mandatory 锚点 = v1.8 `anchor: true` 的子集(标 `mandatory: true`)?prohibited outcome 如何形式化到可校验(纯文本给 LLM 看 vs 结构化谓词可机器校验)?**Hassan 倾向**:结构化 mandatory_anchors(机器校验可达)+ 文本 prohibited(LLM 软约束)+ 关键不可逆事实(死亡/归属)结构化禁改集。

### Q2 — director 权限词汇（最关键)
director 提议的事件能 mutate 什么?
- (a) 仅「软」状态(关系/flag/var/flavor NPC)—— 略宽于 L3,但不能真推进主线大事件。
- (b) 「软」+ 受限「硬」(可触发 world_event、引入次要 NPC、局部派系摩擦),但**禁**不可逆 backbone 级(死亡/归属/灭门)+ 禁 player-exclusive。
- (c) 近乎全权,仅 backbone prohibited + mandatory 可达兜底。
- **Hassan 倾向**:**(b)** —— L4 要能「演」(产生方向性事件),但 backbone 级不可逆 + 玩家关键抉择保留。具体词汇 + 「不可逆」判定(哪些 effect 算不可逆)待拍。

### Q3 — 可达性守门（L4 根本难点)
director 改了走向后,如何保证 mandatory 锚点仍可达?
- L3 的「不改任何未来事件 condition」**不适用**(director 就是要改)。
- 候选:**应用前**对每个 pending mandatory 锚点,验「在 director 提议应用后的世界,仍存在一条满足其前置的可达路径」(可能需前向模拟 / 约束求解)。失败 → 拒绝该提议(spike §3.4 snapshot revision/precondition retry)。
- **Hassan 倾向**:M1 先做**保守版** —— mandatory 锚点的前置谓词读集合**禁止被 director 提议的 effect 写**(类似 L3 非干涉,但**只**护 mandatory 锚点,不护普通事件 → 给 director 留演化空间);完整「前向可达模拟」留后续 milestone。**待拍**:保守非干涉 vs 真前向模拟。

### Q4 — plot ledger 设计（长程连贯)
spike §2 分层记忆:backbone / 世界快照 / **plot ledger**(unresolved threads / promises / secrets-who-knows / 完成锚点 / 废分支 / 因果事实,带 ID+source+时间+失效)/ rolling digest(近期逐字 + 远期 arc 摘要,不可逆事实单独保全)/ director plan state(当前 arc / 目标张力 / 下一 beat 意图 / cooldown / 上次接受拒绝理由)。
- 全建 vs 分阶段?**Hassan 倾向**:M2 先 plot ledger 核心(threads + 完成锚点 + 不可逆事实)+ rolling digest;director plan state + secrets-who-knows 后置。每条事实**结构化 + 稳定 ID**,可被检索/失效,**绝不**让生成 prose 回流成事实(继承 L3 反馈环禁令)。

### Q5 — 持久化 / 确定性 replay
director 提议(事件 + effects + ledger delta)固化进 save,reload 确定性 replay 不重询(继承 L3 冻结缓存)。键怎么扩(L3 = gap+月+locale;L4 director beat 不在 gap 内,需 director-turn 序号 + plan 版本 + locale)?spike §5.4:模型不可得 / 版本变更时能否 replay → 存 normalize 后事件 + ledger delta(非模型原始响应/思维链),replay 只读已存。**Hassan 倾向**:director-turn 索引 + backbone hash 入键;reload 走已固化 director 事件序列。

### Q6 — 调度 / 优先级仲裁
spike §3 月序:机制 phase → fire mandatory 锚点 → post-anchor 快照 → 按 cadence/budget/trigger 问 director → 校验(backbone/可达/重复/cooldown/允许 effect)→ 串行应用 accepted → ambient(压制与 mandatory/director 冲突者)→ finalize。优先级类见边界 #4。**Hassan 倾向**:复用 v1.8 phase hook 位置 + cadence;新增 mandatory-anchor-first 排序 + director phase 在其后。

### Q7 — 一致性 critic（spike §2 收尾)
确定性校验(backbone/可达/schema)**之后**,是否再跑一个低成本 LLM **consistency critic**(查矛盾/复活死者/重复 beat)?**Hassan 倾向**:M4 加,确定性校验为主、critic 为辅(不阻塞,失败仍可降级)。

### Q8 — 长程漂移 benchmark（spike §5.2,最大未知)
如何**自动检测**几十年尺度的漂移 / 遗忘死亡 / 重复 beat / 违反锚点?spike §4 只验了 4 轮短程。**Hassan 倾向**:专列一个 milestone 做长程仿真 harness(跑 N 年,断言:所有 mandatory 锚点触发 / 无死者复活 / 无 backbone 违禁 / beat 多样性阈值)。这是 L4「可验」的核心交付,也是最大工程未知。

### Q9 — 成本 / 延迟预算
spike §5.5 + §3:LLM 延迟不得长持模拟锁 → 提前规划数 beat(revisioned snapshot)或短超时跳过。per-turn token/call 预算 + cadence(继承 v1.8)。**Hassan 倾向**:同步有界批量(继承 L3 Q1b)起步;异步 plan-ahead 留后续。

### Q10 — prompt 注入 / mock（继承 v1.8)
继承 v1.8:authored/backbone 字段 `_clip` + fenced 净化(Q10);可注入 director generator + fixtures(成功/超时/坏输出/违 backbone/违可达)不烧真 LLM。
