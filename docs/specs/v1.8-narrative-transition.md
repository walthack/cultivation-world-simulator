## 边界（锁死,先于一切）

> **v1.8 = LLM 生成「锚点之间」的过渡剧情。剧本定大走向(锚点),LLM 填中间。半 AI。**

这是阶梯上第一次让 LLM 碰**「发生什么」**——但**被锚点夹住**。和 v1.7 的根本区别:

| | v1.7 (L2) | v1.8 (L3) |
|---|---|---|
| 走向(发生什么) | 100% scripted | **锚点 scripted;锚点之间 LLM** |
| LLM 输出 | 仅 narration 展示文本 | 过渡 **beat(受限机制 + narration)** |
| 机制不变量 | fill 开/关 effects 逐字节一致 | **锚点必触发 + 写集合不干涉锚点前置**(见下) |

**L3 的核心承诺(= 本版全部意义)**:无论 LLM 在锚点间生成什么,**每个锚点都必然在其计划月触发,且触发时其前置成立**。LLM 可丰富中段,但**绝不能改变剧本大走向**,也**绝不能让任何后续锚点变得不可达**。

**硬不变量(架构级,不可越界)**:
1. **锚点至上**:锚点是确定性骨架(v1.6 storyline/scripted 事件)。过渡 beat 优先级**永远低于锚点**;同月冲突时 beat 让路,锚点不动。**注意**:dispatch 现按 timeline 顺序、无优先级类(`event_dispatcher.py:49`)——`hard_anchor` 优先级**未落地**,必须新建(见 M0/M1),否则「同月 beat 排在锚点前 → 篡改其 condition/triggered」(starvation #9)。
2. **写集合非干涉(codex 修正 Q3,关键)**:过渡 beat 的**写集合(它会改的 flag/var/relation/entity/triggered/storyline)不得与任何 pending 锚点的前置谓词读集合相交**。守门**不是**「应用后测下一锚点 condition 是否为真」——锚点 condition 到期前本就该为假,且 dispatch 是一次性精确月触发(`event_dispatcher.py:71-108`),当前真值测试既会误杀也会漏检。守门 = **静态 write-set/非干涉校验 + 定时重放**(beat-on vs beat-off,完整锚点 ID 集在同 (year,month) 触发)。
3. **transition 命令 schema,非通用 effect lane(codex 修正 Q2,关键)**:beat 的机制**不走** `apply_effects()`。原因:`apply_effects()` 对非可 pickle 活对象**跳过 rollback 快照**(`effect_applier.py:214-237`)→「先应用再校验再回滚」不安全;registered mod effects 是任意 callable,按 effect 名挡不住(`effect_applier.py:_apply_one`)。改为**独立的、白名单受限的 transition 命令 schema**,经 schema/ID/write-set/staleness 校验后,由专属 applier **确定性应用**。
4. **不可变快照 proposal 边界(codex 修正)**:generator **不接收可变 `world` 句柄**(现状 `filler(requests, world)` 收活 world,`scripted_scenario.py:177-183`,与本边界冲突 → 必须新建 snapshot-only 接口)。generator 收**不可变序列化快照**,只返回**数据**(narration 文本 + 涉及实体 ID + transition 命令 + 优先级/过期),不写代码、不直接 mutate world。
5. **文本隔离**:beat 的 prose **只进 `Event.narration`**(v1.7 已隔离的 render-only 通道),**绝不进 `Event.content`**(content 喂编年史 + AI context,`event.py:36-43` / `narrative_fill.py:_chronicle_context`,回流即污染走向)。beat 文本/计划/缓存元数据**绝不进 `ScriptedScenarioState.state`**(被 `var_equals` 读到,`state_access.py:86-107`)。
6. **降级即纯剧本**:无 LLM key / 失败 / 超时 → 跳过过渡生成,锚点照常按时触发,游戏完整可玩(过渡是连接组织,非必需;不需 authored fallback 文本)。

> v1.9 (L4) 才让 LLM **超越**预设锚点自主演化走向。v1.8 严格是「**锚点间插值**」:LLM 知道从锚点 A 走向锚点 B,只填中间,不改 A/B,不改 A→B 大方向。

## 设计 Q（全文保留作决策依据 + codex 裁决标注）

### Q1 — 「锚点」如何表达 — codex CONCUR
显式 `anchor: true`(默认 false) + 可选 `protected_preconditions`/`protected_outcomes`;引擎把相邻两锚点间的月识别为可插值 gap。锚点可落在 storyline 上(选定线的锚点链)。**codex**:现 dispatch 按 timeline 顺序、无 anchor/优先级概念(`event_dispatcher.py:49`),显式字段优于重载普通事件;但 `anchor`/`protected_*` 均未落地。

### Q2 — 过渡 beat 的机制权限 — codex CONCUR（修正为命令 schema）
(b) 受限白名单。**codex 关键修正**:不是把 effect 子集塞进 `apply_effects()`,而是**独立 transition 命令 schema**。canonical effect lane 含改向操作 `world_event_trigger`/`set_var`/`activate_storyline`/`npc_die`(`effect_applier.py:_apply_one`;`schema_constants.py:25`),且 `apply_effects()` 对活对象跳 rollback 快照(`effect_applier.py:214-237`)、mod effect 是任意 callable → 通用 lane 不安全。初始白名单见决策表 Q2。

### Q3 — 锚点可达性如何保证 — codex DISSENT（重写）
**原方案(已废)**:应用前测下一锚点 condition 是否为真。**codex 反驳(采纳)**:锚点 condition 到期前合法地为假;dispatch 一次性精确月触发(`event_dispatcher.py:71-108`),当前真值测试不能证明未来可达。**新方案**:① 静态 **write-set/非干涉**校验(beat 写集合 ∩ 任一 pending 锚点谓词读集合 = ∅);② **定时重放**守门(beat-on/off,完整锚点 ID 集同月触发,见 Q8/M0)。配合 (b) 白名单双保险。

### Q4 — 生成时机 / cadence / 预算 — codex CONCUR（补 staleness）
cadence + 有界批量,generator 严格 ≪超时(scenario phase await 内联,v1.7 可阻塞 ~30s,`simulator.py:92-94`/`scripted_scenario.py:124,181-186`)+ per-tick 预算。**codex 补**:批量从初始快照生成,earlier beats / 普通 sim phase 会使其失效 → **需 revision/staleness 校验**(v1.7 无 snapshot revision)。逐月同步否决。

### Q5 — 可复现性 / 持久化 — codex DISSENT（重写）
**原方案(已废)**:beat 当普通 fired event 固化即可 replay。**codex 反驳(采纳)**:`Event`/`EventStorage` **无 effects 字段**(`event.py:45-62`/`event_storage.py:82-92`),load 恢复世界状态而非 replay 事件(`load_game.py:125-150`)→ fired event + triggered ids **不能**重放 beat 机制。**新方案**:独立 **normalized beat ledger**(effects + 涉及实体 + 顺序 + 接受状态 + 过期),**非** state(防 `var_equals` 读)、**非** Event;持久化 normalize 后数据(非模型原始响应/思维链);reload 走 ledger 确定性 replay,不重询 LLM。键:`(scenario_id, gap=(prev_anchor_id,next_anchor_id), beat_index, resolved_path, content_locale)`。

### Q6 — 连贯 / 记忆 — codex CONCUR（补预留 + 事实非 prose）
L3 horizon 有界(当前锚点→下一锚点),轻量四件:backbone + 世界快照(ID+短标签) + **下一锚点目标** + 本 gap 已生成 beat。**codex**:`_assemble_within_budget` 会整块切片 → 「下一锚点目标」须**预留空间 + 高优先**,否则被截断;accepted-beat 记忆须存 **normalized 事实,非生成 prose**(防 prose 回流成走向输入)。复用 v1.7 有界组装 + chronicle 仅 authored。完整 plot ledger 出 scope(L4)。

### Q7 — 失败 / 降级 — codex CONCUR
跳过该 gap 过渡,锚点照常触发(不变量 #6)。无 authored fallback(过渡是 opt-in 增量)。**codex 前提**:生成路径**不得延迟或标记锚点**(现 narration 失败已优雅降级,`scripted_scenario.py:173-206`,可借鉴)。

### Q8 — 守门 / 验收 — codex DISSENT（强化非空过)
不变量(锚点必触发 / effect ∈ 白名单 / 写集合不干涉 / 确定性 replay)方向对,但**测试规格不足**。**codex 强制**:① **非空过见证** —— 断言 generator 被调用、≥1 beat 被接受、应用了**非零**白名单 effect;② **确定性初始状态 + RNG**(对抗 `random_chance` 谓词);③ 比对**完整锚点 ID 集**(非只比触发了的,exact-month 静默丢失才能抓到);④ 同测试内放**一个已知允许 + 一个已知禁止**的 effect(防白名单断言对空序列恒真);⑤ 锚点前置须用真谓词(`world_flag`/`var_equals`/relation/NPC/`event_triggered`),**禁用 `always`**(现 storyline fixture 多用 `{"always":{}}`,证不了前置保持)。

### Q9 — Prompt 注入 — codex CONCUR
复用 v1.7 `_clip` + fenced 数据区。transition schema / snapshot 标签 / 锚点目标 / 前 beat 事实**全部**同等净化。

### Q10 — Mock / fixture — codex CONCUR（扩返回类型）
可注入 generator(`make_narrative_filler(call_llm=...)` 已证,`narrative_fill.py:155-180`);但返回类型 `{event_id: text}` **不能直接复用**于结构化 beat → 扩为 beat proposal。fixtures:成功/超时/坏输出/**违规 beat 被拒(断言 call count + proposal 收到 + 拒因 + 零 effect 应用)**/未命中。

### Q11 — Locale — codex CONCUR
按 `content_locale` 生成,缓存键含 locale(`narration_cache.py:27-36`)。**codex**:production 现读全局 `language_manager.current`(`scripted_scenario.py:155-164`)→ 规划 gap 时**显式冻结** run 的 content_locale。
